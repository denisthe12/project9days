# Техническое задание

## Демонстрационная страница для занятия №4

### 1. Цель проекта

Создать простую одностраничную веб-страницу для демонстрации работы с двумя внешними API:

1. Gemini API — формирование учебного плана.
2. API погоды — получение прогноза на завтра.

Проект используется только на занятии. Сложная инфраструктура, база данных, авторизация и деплой не требуются.

---

## 2. Технологии

- Frontend: HTML, CSS и JavaScript.
- Backend: Node.js и Express.
- Gemini: официальный пакет `@google/genai`.
- Погода: Open-Meteo API без API-ключа.
- Секрет Gemini хранится в файле `.env`.

---

## 3. Структура страницы

На одной странице расположены два независимых блока.

### Блок 1. Учебный план

Поля:

- «Тема обучения» — текстовое поле;
- «Срок в днях» — число от 1 до 14;
- кнопка «Сформировать план».

После нажатия кнопки frontend отправляет запрос на собственный backend:

```http
POST /api/study-plan
```

Пример запроса:

```json
{
  "topic": "Основы JavaScript",
  "days": 5
}
```

Backend проверяет данные, формирует prompt и отправляет запрос в Gemini.

Пример смысла prompt:

```text
Составь практический план изучения темы «Основы JavaScript» на 5 дней.
Для каждого дня укажи тему, что изучить и одно небольшое практическое задание.
Пиши кратко, понятно и без лишней теории.
```

Результат выводится на странице по дням:

```text
День 1 — Переменные и типы данных
Что изучить: ...
Практика: ...
```

### Блок 2. Погода на завтра

Элементы:

- список городов: Актау, Атырау, Алматы;
- кнопка «Показать погоду».

Для городов используются заранее заданные координаты:

| Город | Широта | Долгота |
|---|---:|---:|
| Актау | 43.65 | 51.17 |
| Атырау | 47.12 | 51.92 |
| Алматы | 43.24 | 76.95 |

Frontend обращается к собственному backend:

```http
GET /api/weather?city=Aktau
```

Backend запрашивает прогноз Open-Meteo на следующий день и возвращает:

- название города;
- дату;
- минимальную температуру;
- максимальную температуру;
- краткое описание погодных условий;
- вероятность осадков, если доступна.

---

## 4. Работа с Gemini API

Настройки хранятся в `.env`:

```env
GEMINI_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-3.7-flash
PORT=3000
```

В репозитории должен находиться безопасный пример:

```env
# .env.example
GEMINI_API_KEY=
GEMINI_MODEL=gemini-3.7-flash
PORT=3000
```

Файл `.gitignore` должен исключать `.env`:

```gitignore
.env
.env.*
!.env.example
node_modules/
```

API-ключ используется только на backend и не передаётся в браузер.

---

## 5. Состояния интерфейса

Для обоих блоков необходимо предусмотреть:

- состояние загрузки;
- отключение кнопки во время запроса;
- вывод полученного результата;
- понятное сообщение при ошибке;
- возможность повторить запрос.

Примеры сообщений:

- «Формируем учебный план…»;
- «Загружаем прогноз…»;
- «Не удалось получить ответ Gemini. Повторите попытку»;
- «Не удалось загрузить погоду».

Технические ошибки и API-ключ не должны выводиться пользователю.

---

## 6. Ограничения

- Без регистрации и авторизации.
- Без базы данных.
- Без сохранения истории запросов.
- Без автоматического определения города.
- Без сложного дизайна и адаптивной вёрстки.
- Без прямого обращения к Gemini из браузера.
- Не добавлять функции, не связанные с двумя демонстрационными сценариями.

## 8. Критерии готовности

Проект считается готовым, если:

1. Страница запускается локально одной командой.
2. Пользователь вводит тему и срок и получает план от Gemini.
3. План содержит отдельный раздел для каждого дня.
4. Пользователь выбирает один из трёх городов и получает погоду на завтра.
5. Во время запросов отображается состояние загрузки.
6. Ошибки показываются понятным сообщением и не ломают страницу.
7. Gemini API-ключ отсутствует во frontend-коде и `.env.example`.
8. На странице находятся только две основные кнопки: «Сформировать план» и «Показать погоду».
